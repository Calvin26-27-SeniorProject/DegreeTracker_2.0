## What this is

Ken Arnold's personal academic website (kenarnold.org), built with [Quarto](https://quarto.org/) as a static site. Content is Markdown/`.qmd` files with YAML frontmatter; Quarto renders them to `_site/`, which is deployed.

## Commands

- `quarto preview` — live-reload local dev server.
- `quarto render` — build the site into `_site/`.
- `make all` — copies the CV and research statement PDFs in from Dropbox (`static/kcarnold_cv.pdf`, `static/kcarnold_research_statement.pdf`), then runs `quarto publish gh-pages --no-prompt --no-browser` to build and publish to the `gh-pages` branch. This assumes Ken's local Dropbox paths exist, so it's only runnable on his machine.
- `make check` — greps the repo for `draft: ` frontmatter and `TODO` markers, to find posts/pubs not ready to publish.
- `uv run backend/gen_pubs.py` — reads `~/Dropbox/Ken/Docs/CV/my_pubs.yml` (not in this repo) and scaffolds a new `pubs/<slug>/index.qmd` for any publication that doesn't already have a directory under `pubs/`. Existing pub pages are never overwritten. Generated pages still need a `featured.png` and abstract review before publishing.

There is no test suite or linter for this repo; correctness is "does `quarto render`/`quarto preview` work and does the page look right."

## Structure

- `backend/` — repository automation and content-generation scripts. This is tooling rather than a deployed web server; the site currently has no application backend.
- `backend/data/` — source data used by generated or computational pages, such as the advising course schedule.
- UI/UX — the Quarto pages and presentation layer remain at the repository root so Quarto can preserve the existing site URLs and asset paths.
- `_quarto.yml` — site-wide config: nav bar, theme (`cosmo` + `styles.css`), Google Analytics, project output dir (`_site`).
- `posts/` — blog posts, one subdirectory per post (dir name = URL slug) each containing `index.qmd`. `posts/_metadata.yml` sets shared frontmatter defaults (author, `freeze: true`, title-block banner, utterances comments wired to this repo). `posts.qmd` is the listing page.
- `pubs/` — one subdirectory per publication, each with `index.qmd` plus assets (`featured.png`, poster PDFs, etc.). Pages here are normally generated by `backend/gen_pubs.py` from an external YAML source of truth and then hand-edited (abstract, links, student-author callouts). `pubs.qmd` is the listing page.
- `static/` — files served as-is (CV PDF, research statement PDF, standalone HTML mini-apps like `timer.html` and `lm-internals.html`, images). Referenced directly from `_quarto.yml`'s `resources:` and from nav links.
- `static/images/` — site presentation images, including profile-photo variants used by the home page.
- `index.qmd`, `bio.md`, `projects.qmd`, `ideas.qmd` — top-level pages.
- `_freeze/` — Quarto's cached computational output (per the `freeze: true` setting in `posts/_metadata.yml`); don't hand-edit.
- `wrangler.jsonc` — Cloudflare Pages/Workers config for serving the built `_site` as static assets.

## Conventions

- Post/pub frontmatter is standard Quarto YAML (`title`, `date`, `author`, `categories`, etc.). Draft content should be marked `draft: 1`/`draft: true` in frontmatter so `make check` and Quarto's own draft handling can find it before it's published.
- Pub pages use `{{< meta field >}}` shortcodes to reuse frontmatter values (e.g. `abstract_long`, `url_pdf`, `publication_short`) in the body rather than duplicating text.
- Undergraduate co-authors are flagged with a `::: {.callout-important}` note near the top of the pub page (see `backend/gen_pubs.py`'s `generate_quarto_content` for the exact pattern) — preserve this when adding/editing pub pages.
- Comments on posts use the `utterances` GitHub-issues-based system, configured once in `posts/_metadata.yml`.
